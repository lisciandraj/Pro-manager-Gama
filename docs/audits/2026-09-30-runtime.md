# Coco ERP — audit complémentaire du chargement et de la maintenance

Date : 30 septembre 2026. Révision de départ : `bbcc400100a74d2bf0533778b44f3682352788eb` (première restructuration livrée par la PR #91).

Cette passe prolonge l’[audit de l’organisation et des domaines](2026-09-30.md). Elle examine les points d’entrée HTML, le graphe de chargement, tous les usages du moteur PDF dans `src/`, les intégrations Projets/CRM/achats/notifications, les observateurs DOM concernés, les dépendances npm, les contrôles de génération et la documentation courante. Les conseils de la base de production et ses versions ont été consultés en lecture seule.

## Corrections livrées

| Constat | Correction | Effet vérifiable |
| --- | --- | --- |
| jsPDF de 365 730 octets chargé à chaque ouverture, même sans export | Chargement local à la première demande via `GamaPdf.ready()` | Aucun téléchargement de ce moteur à l’accueil ; intégrité conservée et nouvelle tentative possible après erreur |
| Les alertes et liens Projets imposaient le chargement de tous les écrans | Intégration légère séparée, moteur de calcul puis écrans chargés à l’ouverture | Compteur et résumés clients disponibles sans télécharger l’éditeur |
| Appels communs dupliqués et requêtes d’alertes simultanées | Transport partagé, une promesse commune pour les seules lectures simultanées | Moins de requêtes dupliquées ; chaque actualisation ultérieure relit le serveur |
| Réponses anciennes et fermeture intempestive d’un formulaire lors d’un renouvellement de jeton | Invalidation par session, protection contre les réponses hors ordre, distinction `TOKEN_REFRESHED` | Ancien compte rejeté ; renouvellement normal sans perte du formulaire Projets |
| Observateur Notifications inspectant chaque mutation du document pour des boutons absents | Suppression de cet observateur ; badge détenu par la barre d’en-tête | Suppression d’un travail récurrent sans modifier les alertes |
| Vite 6.4.1 signalé par npm audit | Mise à jour corrective verrouillée en 6.4.3 | Audit npm : 1 paquet vulnérable avant, 0 après |
| Documentation décrivant encore Projets et jsPDF comme chargés au démarrage ; chemin de migration historique erroné | Architecture, guides, cartographie et modules mis à jour ; guide PDF ajouté | Points d’entrée et contrats actuels documentés |
| Absence de seuil global sur les scripts de démarrage | `npm run check:startup` exécuté en CI | Budget de 93 scripts et 1 900 000 octets non compressés |

Les fichiers source portent des noms métier dans `src/features/`. Les anciennes adresses `gama-*`/`architect-*` restent des sorties générées compatibles ; les renommer publiquement casserait des contrats existants. L’intégration extraite est nommée `integration.js`, publiée en `coco-project-integration.js`. Les identifiants de base, clés de stockage et API publiques sont conservés.

Une mesure réseau sur le téléphone réel reste nécessaire pour quantifier ce délai.

## Sécurité et base de données

Le correctif Vite concerne l’outil de développement ; le site GitHub Pages sert des fichiers statiques et n’exécute pas ce serveur. Voir les avis officiels [WebSocket](https://github.com/vitejs/vite/security/advisories/GHSA-p9ff-h696-f583) et [contrôle des fichiers Windows](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff). `npm audit` ne couvre pas automatiquement les copies manuelles de bibliothèques dans `assets/vendor/` et ne constitue pas un audit de toutes les règles métier.

Le relevé Supabase reste identique à la première passe : 5 groupes d’index identiques, 26 alertes d’évaluation auth dans les politiques RLS, 110 politiques permissives multiples, 163 clés étrangères sans index de couverture, 69 index non utilisés dans la période observée, 16 tables privées avec RLS sans politique et une alerte sur la protection contre les mots de passe compromis. Ces avertissements ne sont pas déclarés corrigés par cette livraison frontend. Supprimer des index ou politiques à partir de leur seul compteur ne permettrait pas de garantir l’intégrité des accès.

Le serveur observé est PostgreSQL **17.6**. Le [changelog Supabase du 25 septembre](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes) annonce 17.11 et des changements de compatibilité à contrôler avant maintenance. Les extensions `ltree` et `btree_gist` ne figurent pas dans les extensions installées relevées ; `pgcrypto` est présent. Une mise à niveau doit suivre les contrôles et sauvegardes de la procédure Supabase. Aucune mise à niveau de moteur, migration SQL ou modification de donnée métier n’a été effectuée pendant cette passe.

## Validation

Les tests ciblés ajoutent des vérifications comportementales : absence du moteur à l’accueil, chargement unique et ordonné, reprise après panne, construction de vrais PDF, intégrité des pièces jointes et des téléchargements, invalidation d’une ancienne session, maintien des clés d’idempotence et absence de cache durable des alertes.

La validation locale couvre construction, syntaxe, types, documentation, budget, génération reproductible et tests Node/SQL isolés. Les parcours navigateur sont exécutés par GitHub Actions sur la révision de la PR, notamment PDF/entreprise, Projets, TMS, permissions, scanner, ajustements de stock et interface partagée. Les workflows et leurs résultats sur le commit final sont la référence de validation ; les données de production ne sont pas utilisées comme fixtures.
