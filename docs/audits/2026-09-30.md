# Audit technique Coco ERP — 30 septembre 2026

## Périmètre et méthode

Révision de départ : `548d4cbc0e80d6861588e653eed0342a423d14d4`.
Inventaire de **748 fichiers suivis**, lecture de 214 fichiers de code, configuration et documentation, puis des sources et tests complémentaires concernés. Analyse des points d’entrée, chargement, cache, dépendances globales, organisation, documentation et couverture des tests. Consultation en lecture seule des alertes Supabase, des métadonnées de migrations/fonctions et des statistiques de tables.

Il s’agit d’un audit du code et de l’exploitation observable, pas d’une certification de chaque règle métier. Aucun stock, document fiscal, utilisateur, permission ou donnée d’entreprise n’est corrigé sur une supposition.

## Base Supabase : observations au moment de l’audit

Production : 216 entrées dans l’historique de migrations ; 218 fichiers dans le dossier actif du dépôt. Les anciens scripts, la baseline et les noms/timestamps distants doivent être comparés via la procédure de restauration, pas en concluant automatiquement à des migrations manquantes.

Les conseils Supabase ont signalé :

| Alerte | Nombre de constats | Interprétation et suite |
| --- | ---: | --- |
| Protection des mots de passe compromis | 1 | Vérifier et activer dans Auth si disponible pour l’offre ; action de configuration distincte |
| Index identiques | 5 groupes | Examiner les contraintes qui les utilisent avant de retirer un doublon |
| Appels auth dans les politiques RLS | 26 | Étudier une évaluation par requête avec tests des permissions avant/après |
| Politiques permissives multiples | 110 | Examiner leur combinaison ; leur suppression peut retirer un accès légitime |
| Clés étrangères sans index de couverture | 163 | Prioriser les jointures/suppressions réellement lentes ; pas de création aveugle de 163 index |
| Index non utilisés dans les statistiques | 69 | Un compteur nul ne prouve pas l’inutilité ; tenir compte de la période observée |
| RLS activé sans politique | 16 | Tables privées de traitement ; refus par défaut à distinguer d’une exposition publique |

Groupes d’index identiques : hr_employees, purchase_orders, return_credits, stock_movements et tms_deliveries.
La plus grande table du relevé public avait environ 1 336 lignes estimées ; products environ 217. Ces statistiques ne sont ni un comptage comptable ni un test de charge. Elles ne justifient pas, seules, une migration de moteur de base.

## Validation et limites

Les contrôles reproductibles sont enregistrés dans les workflows GitHub : génération, syntaxe, types, migrations, tests unitaires, tests d’architecture et parcours navigateur. Le résultat final doit être lu sur la révision effectivement fusionnée ; les premiers essais et leurs corrections restent traçables.

La nouvelle couverture vérifie le chargement partagé, la reprise après échec, l’absence des modules différés à l’accueil, les liens directs, l’isolation du cache des pages et la propriété des sources générées. Les suites existantes couvrent notamment ventes, achats, stocks, retours, permissions et traductions.

Limites : pas de mesure chronométrée avant/après sur le téléphone réel, pas de test de charge production, pas de certification fiscale, pas d’examen de secrets serveur. Les chiffres de gains annoncés ci-dessus sont des tailles de fichiers et mécanismes vérifiés, pas une promesse de latence universelle.

## Ordre conseillé pour la suite

1. Mesurer une session mobile réelle : ouverture froide, ouverture répétée, recherches et listes volumineuses.
2. Traiter les 5 groupes d’index identiques et les politiques RLS les plus coûteuses sur une base de test, puis comparer droits et plans.
3. Extraire les dépendances PDF et les fonctions d’alertes Projets pour différer le reste sans casser les appels synchrones.
4. Réduire progressivement les modules IIFE les plus volumineux avec tests de parcours ; conserver les adresses publiques tant que des clients les utilisent.
