# Architecture GAMA

Audit standard du site public GAMA de Coco ERP, commit 8569f2e52c2e0fcdd5d036a73fb039522b49841a. Le catalogue Cloudflare Pages utilise HTML/JS, un proxy Pages Functions vers Supabase PostgreSQL et Auth. Visiteurs publics: catalogue projeté, devis, demandes de commande sans paiement, reçus invités par capability, avis vérifiés, demandes de droits et retours. Clients B2B: appartenance explicite et active, société déduite du compte, tarifs et documents privés, approbations. Administrateurs: réglages, publication et conformité sous droits website et MFA.

Entrées: functions/_middleware.js, functions/api/storefront.js et surveys.js; scripts navigateur site.js, commerce.js, b2b.js, surveys.js. Le client B2B utilise aussi des RPC Supabase directement. Façades SECURITY INVOKER vers implémentations SECURITY DEFINER avec search_path vide et contrôles internes. Les tables privées sont révoquées/RLS. Projections publiques excluent coûts, stocks exacts et autres clients. Le proxy impose corps borné, liste actions, origine, IP Cloudflare, secret et Turnstile sur les écritures publiques. Les prix et quotas se recalculent en SQL; les conditions acceptées sont versionnées.

Les migrations sont ordonnées; les wrappers successifs et helpers finaux doivent être suivis. Aucun historique machine compatible coverage-ledger/findings disponible; l’audit prose 29 octobre est contexte à revalider. Aucun constat confirmé antérieur à exclure. L’ERP interne hors dépendances du site est hors périmètre. Pas de comparaison tierce fiable.

Build storefront Node core possible; build ERP et tests SQL/navigateur dépendent de paquets absents. Aucun téléchargement dans cette passe. Exécution cible seulement via sandbox parent vérifié; agents chasse en lecture source uniquement. Les contrôles déployés, secrets et politiques effectives ne sont pas prouvés par le dépôt. Companions sélectionnés: Web/protocole/Auth, client-side, isolation/lifecycle, supply-chain/release, cloud/deployment, ressources, car ces frontières sont visibles.
